# Сбор данных

## Источник

Аналитический портал ФНС России, раздел «Налоговые паспорта субъектов Российской Федерации»: https://analytic.nalog.gov.ru/. Справочно: описание портала в базе знаний «Открытые госфинансы» — https://infoculture.github.io/finguide/data-sources/federal/analytic-nalog-gov-ru.

Портал — одностраничное приложение. Его API найден в JS-бандле `main.<hash>.js`. Базовый адрес — `https://analytic.nalog.gov.ru/api`. Все ответы JSON имеют вид `{"data": ...}`.

| Метод | Запрос | Что возвращает |
|---|---|---|
| `GET /TaxPassports/MaxYear` | — | последний доступный год (`2024` на 03.11.2026). Список периодов на портале — от 2014 до MaxYear |
| `GET /TaxPassports/Regions` | — | субъекты: `id`, `label`, `code` (код региона), `parentId` (id округа), `year`, `yearForPassport` |
| `GET /TaxPassports/FederalRegions` | — | РФ (`code = 0`) и федеральные округа (`code` 101–109) |
| `GET /TaxPassports/Maps` | — | разделы паспорта для карты: `id` (= номер раздела), `name`, `startYear`, `endYear`, `hint` |
| `POST /TaxPassports/Indicators` | тело `{"params": {"year": 2024, "federalRegionId": 0, "mapId": 1}}` или `regionId` вместо `federalRegionId` | ключевые показатели раздела по территории |
| `GET /TaxPassports/IndicatorData/{year}/{indicatorId}` | — | значения показателя по всем территориям: `value`, `difference`, `regionId` или `federalRegionId` |
| `GET /TaxPassports/Export` | `year`, `federalRegionId` или `regionId` | паспорт одной территории (XLS) |
| `GET /TaxPassports/ExportAll` | `year` | ZIP со всеми паспортами года. Для года вне диапазона — HTTP 400 |

Кроме того, все методы принимают необязательный параметр `taxPassportsVersionId`: фронтенд берёт его из адресной строки. Публичного списка версий нет, коллектор его не использует.

Внимание: тело POST оборачивается в `params` (так его отправляет axios во фронтенде). Без обёртки сервер отвечает 400 «Модель не заполнена».

## Доступ из-за рубежа

`analytic.nalog.gov.ru` не отвечает на запросы с зарубежных IP: TCP-соединение обрывается по таймауту. Нужен российский выход в интернет. Варианты:

1. **SOCKS5-прокси с российским выходом.** Коллектор читает адрес прокси из переменной `REGTAX_PROXY`, httpx поддерживает схемы `socks5://`, `socks5h://` и `http://`. В этой работе использовался локальный контейнер `awg-proxy` из проекта rulawmon: AmneziaWG-туннель в московский ЦОД с SOCKS5 на `127.0.0.1:1080`.

   ```bash
   REGTAX_PROXY=socks5h://127.0.0.1:1080 make collect
   ```

   Проверка доступности:

   ```bash
   curl -x socks5h://127.0.0.1:1080 -s -o /dev/null -w "%{http_code}\n" https://analytic.nalog.gov.ru/api/TaxPassports/MaxYear
   ```

2. **Запуск на сервере в России.** Прокси не нужен: достаточно склонировать репозиторий, выполнить `make venv collect`, а потом перенести `data/raw/` обратно.

Ключи и конфигурации VPN в репозиторий не кладутся.

## Запуск

```bash
make venv                                          # .venv и зависимости (uv)
REGTAX_PROXY=socks5h://127.0.0.1:1080 make collect # скачать
make build                                         # собрать DuckDB и Parquet
make catalog                                       # обновить docs/catalog/
make test
```

Параметры коллектора (`python -m regtaxpassports.cli collect --help`):

- `--years 2023-2024` — только указанные годы (по умолчанию от 2014 до `MaxYear`);
- `--force` — перекачать уже скачанные файлы (по умолчанию докачиваются только отсутствующие);
- `--skip-indicators` — не скачивать показатели карты.

Переменные окружения: `REGTAX_PROXY`, `REGTAX_INTERVAL` (пауза между запросами, по умолчанию 1 с), `REGTAX_TIMEOUT` (180 с), `REGTAX_USER_AGENT`.

Нагрузка на портал: справочники — 4 запроса; архивы — 11 запросов по 6–7 МБ; показатели карты — 114 POST и 706 GET в сумме за все годы. Полный сбор занимает около 20 минут при паузе 1 с. При ответе 403 или 429 коллектор останавливается и не пытается обойти ограничение.

## Что сохраняется

```
data/raw/
  manifest.json                  размер, sha256 и content_sha256 каждого архива, время загрузки
  exports/<год>.zip              ExportAll за год, как пришёл с портала
  api/MaxYear.json, Regions.json, FederalRegions.json, Maps.json
  api/indicators/<год>/map_<mapId>.json      ответ Indicators по РФ
  api/indicator_data/<год>/<id>.json         ответ IndicatorData
  snapshots/<дата>/<год>.zip     прежние загрузки (для учёта пересмотров)
```

`sha256` архива меняется при каждой загрузке: ZIP собирается на лету с текущей датой файлов. Сравнивать загрузки нужно по `content_sha256` — хэшу имён, CRC и размеров файлов внутри архива.

## Пересмотры

ФНС заменяет опубликованные паспорта без объявления. Чтобы фиксировать изменения:

1. Перед новой загрузкой перенесите текущие архивы в снимок:
   ```bash
   mkdir -p data/raw/snapshots/$(date +%F) && mv data/raw/exports/*.zip data/raw/snapshots/$(date +%F)/
   ```
2. Скачайте заново: `make collect`.
3. Соберите базу: `make build`. Файлы снимка, у которых sha256 отличается от текущих, сравниваются по ячейкам. Результат попадает в `passport_revision` и `value_revision`, а в лог выводится строка вида «снимок 2025-03-20: НП_2023_РОССИЙСКАЯ ФЕДЕРАЦИЯ.xls изменён, ячеек: 4».
4. Если снимок полностью совпал с новой загрузкой (`content_sha256` в манифесте тот же), каталог снимка можно удалить.

История загрузок:

| Дата | Годы | Примечание |
|---|---|---|
| 2025-03-20 | 2014–2023 | первая загрузка (`download.sh` на wget), лежит в `data/raw/snapshots/2025-03-20/` |
| 2026-11-03 | 2014–2024 | добавлен 2024 год. Изменился один файл: `НП_2023_РОССИЙСКАЯ ФЕДЕРАЦИЯ.xls` (пересмотр ВВП, 4 ячейки раздела 1) |

## Ежегодное обновление

Новый год появляется на портале, когда меняется `MaxYear`. Порядок обновления:

1. Выполните шаги из раздела «Пересмотры» (снимок и `make collect`). Коллектор сам скачает годы до нового `MaxYear`.
2. Выполните `make build`. Если появятся предупреждения (`data/db/build_report.json` → `warnings`), значит, шаблон изменился. Типичные причины: новый заголовок раздела, который не распознаёт `THEMES` в `regtaxpassports/parse.py`, или сдвиг шапки.
3. Выполните `make test`. Тест `test_every_sheet_has_theme` упадёт, если тема какого-то листа не определилась.
4. Выполните `make catalog` и добавьте строку в таблицу «История загрузок».
